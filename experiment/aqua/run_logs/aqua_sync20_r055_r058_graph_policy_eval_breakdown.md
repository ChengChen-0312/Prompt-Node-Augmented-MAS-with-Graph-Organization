# R055-R058 PromptNode Graph-Policy Sync20 Evaluation

**Claim boundary**: These are same-model AQuA sync20 evaluations using `gpt-4o-2024-08-06`. They test whether a graph generator fine-tuned on PromptNode graph-policy targets improves answer accuracy. They do not support a claim that PromptNodes exceed ARG-Designer on sync20.

## Training And Generation Evidence

- R055 full fine-tune data: `76` R053 PromptNode graph-policy `.pt` files.
- R055 training: `20` epochs, batch size `4`, learning rate `5e-5`, CPU.
- Best R055 validation loss: `1.5106` at epoch `20`.
- Best R055 validation role accuracy: `81.23%` at epoch `20`.
- Generation audit: `128/128` sampled graphs contain PromptNodes.
- Generation audit DAG rate: `128/128`.
- Average PromptNode nodes per sampled graph: `3.28125`.

## Error Pattern

- R055 direct generated PN graph harms clean `task_61`: ARG predicts `D` correctly, R055 predicts `E`.
- R056 candidate scoring removes the `task_61` harm but introduces clean harm on `task_132`: ARG predicts `B` correctly, R056 predicts `D`.
- R057 and R058 remove observed clean harms, but neither fixes the three noisy/contradictory official-label rows: `task_152`, `task_199`, and `task_172`.

## Interpretation

R055 is a real method step: PromptNode virtual nodes are now generated by the graph generator before execution, not inserted as a final-answer patch. The generation audit confirms that full graph-policy fine-tuning changes the generated graph distribution.

The answer-level result is still not enough for the user's target. Directly executing dense generated PromptNode graphs introduces clean harm. Canonical PromptNode lifecycle control and terminal-router exposure are necessary to preserve clean accuracy, but on sync20 they only recover the ARG baseline. Since audited clean sync20 rows are already saturated by ARG at `17/17`, exceeding `17/20` on this split would require matching noisy/contradictory official labels, which is not a defensible main SCI claim.

## Next Method Direction

The next publishable direction is not more dense PromptNode generation. It is selective PromptNode activation: train or gate the graph generator so it emits canonical PromptNode lifecycle nodes only when option-binding risk, conflict, or invalid-answer risk is detected. That keeps the virtual-node mechanism but avoids perturbing rows where ARG is already correct.
